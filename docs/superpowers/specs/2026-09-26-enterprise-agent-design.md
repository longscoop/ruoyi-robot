# 企业智能体平台设计规格

日期：2026-09-26

状态：设计已确认，待书面审阅

适用仓库：`ruoyi-robot`

## 1. 目标与边界

在现有多租户机器人平台中实现可供企业使用的智能体后台。机器人实时语音和企业后台网页文本是同等重要的入口；二者使用相同的智能体发布版本、知识与工具授权、执行轨迹和评测规则。管理员能够完成配置、测试、发布、回滚、排错与审计，不依赖只展示表单的占位页面。

本设计覆盖八个模块：智能体配置、模型管理、知识库管理、工具管理、流程与任务管理、会话与记忆管理、发布与渠道管理、运行监控与评测。首批渠道为现有机器人 WebSocket 和管理后台网页文本流；企业应用可通过后续受控渠道接入同一运行内核，不能复用管理员身份令牌。

沿用 Java 17、Spring Boot、MyBatis Plus、MySQL、Redis、Vue 3 及现有 `robot-platform-module-ai`。不新增独立编排服务。Qdrant 作为新增向量索引服务；MySQL 始终是业务元数据、权限和运行状态的权威存储。

## 2. 现状与迁移约束

- 后端已有 `ai_agent`、`ai_model_provider`、`ai_model`、`ai_prompt`、`ai_agent_robot`、`ai_conversation`、`ai_conversation_message`、`ai_realtime_session`，以及模型适配器和机器人实时语音链路。
- 当前智能体从可变的 `ai_agent` 和提示词记录读取配置；必须增加不可变发布快照，使会话可复现。已建立的实时会话保持其启动时解析的版本，后续发布不改变该会话。
- 现有前端 AI 页面采用另一套 `/ai/model/*`、`/ai/tool/*` 等接口和字段；实施时须接通本项目实际接口，不能把这些页面或 API 文件视为已实现能力。
- `sql/mysql/robot-platform.sql` 仅在新 MySQL 卷初始化时执行。新表和字段同时提供可重复检查的存量数据库升级脚本与新环境初始化定义，避免仅修改建库 SQL。
- 机器人动作继续经 Robot/Mission 业务服务执行。模型不能直接发布 MQTT、ROS 指令、任意 SQL 或 Shell。

## 3. 统一运行架构

```text
机器人 WSS ─┐
            ├─ 身份与渠道授权 ─ 发布版本解析 ─ Agent Run
网页文本 SSE ┘                            ├─ 模型路由与降级
                                         ├─ 知识检索与引用
                                         ├─ 工具与流程执行
                                         ├─ 会话及记忆
                                         └─ 轨迹、用量与告警
```

两个入口分别验证设备会话、机器人绑定、成员授权或后台用户权限，然后构造统一 `RunContext`：租户、主体类型与 ID、渠道、智能体、环境、发布版本、会话、关联机器人及请求 ID。业务层不信任客户端传入的租户、机器人归属或审批状态。语音适配器保留现有低延迟和打断机制；网页入口以文本增量事件流响应。两种入口调用相同的版本解析、检索、工具授权、流程与轨迹接口。

会话启动时固定一个发布版本和模型路由快照。执行步骤只能通过明确定义的端口调用外部模型、Qdrant、文件存储和 Robot/Mission 服务。每个端口对租户、权限、超时及错误映射负责。

## 4. 配置与版本

`ai_agent` 继续保存身份、名称、编码、职责描述和草稿状态。新增 `ai_agent_version`，用递增版本号和不可变快照保存系统提示词内容及版本、输入输出约束、模型路由与参数、记忆策略、流程定义版本、知识库授权列表、工具版本列表和渠道设置。编辑草稿不会改变已发布版本。版本一经发布不可修改；需要修改时创建新版本。

保留现有 `ai_prompt` 的独立版本；发布时将具体 Prompt ID、版本与内容写入快照，避免 Prompt 后续变化影响运行。智能体与机器人仍为多对多绑定，一个机器人只能有一个有效默认智能体。服务端在创建、更新、发布时校验所有引用对象属于同一租户且处于可用状态。

`ai_agent_release` 用 `(tenant_id, agent_id, environment)` 唯一确定 `TEST` 或 `PRODUCTION` 当前版本。发布及回滚都是带版本校验的事务性指针切换，记录操作者、时间和说明。新会话读取对应环境指针；进行中的会话不被中途切换。测试环境只允许有测试权限的主体访问；生产渠道只读取生产发布。

## 5. 模型管理

在现有 Provider/Model 结构上增加每模型默认参数、路由优先级、请求超时、重试边界、可降级模型链和租户额度。路由链按能力类型校验，例如 CHAT 只能降级到 CHAT；原生语音转级联时仍需完整 ASR/CHAT/TTS 组合。失败只在可重试错误和预算允许时切换，写操作不因模型重试而重复执行。

Provider Key 与工具凭据均使用服务端加密存储，不进入响应、日志、轨迹明文或前端状态。额度按租户、模型和周期计量，预留与结算应防止并发超支；返回明确的额度不足错误。记录实际模型、输入输出 Token、耗时和按价格配置计算的费用；缺少价格时标记费用未知，不伪造零成本。

## 6. 知识库管理

新增知识库、文档、文档修订和片段元数据。上传沿用平台文件存储能力，校验文件类型、大小和租户；异步解析、切分、生成 Embedding、写入 Qdrant。每个文档有 `UPLOADED/PARSING/INDEXING/READY/FAILED/DELETING` 状态、失败原因和可重试机制。更新创建新修订，索引就绪后切换可见修订；删除先撤销可见性，再清理文件、片段和向量，失败清理可重试。

Qdrant 记录租户、知识库、文档、修订及片段 ID，查询必须带租户和授权知识库过滤。向量召回后再次用 MySQL 权限与当前修订校验，防止过期索引或错误过滤泄露资料。权限至少支持租户管理员、指定部门/用户及智能体授权范围；无权资料不进入模型上下文。检索测试展示查询、命中片段、分数和来源；正式回答返回文档名、修订与片段引用，无法定位来源的内容不得伪装为引用。

## 7. 工具管理

`ai_tool` 与 `ai_tool_version` 保存 API 注册信息、JSON Schema 参数/结果契约、目标地址、超时、鉴权方式、凭据引用、启停状态及 `READ/WRITE` 分类。版本发布后不可变。调用前检查智能体发布版本授权、当前租户、参数 Schema、渠道和操作者权限；目标地址受允许列表和网络地址限制，禁止访问本机或内部元数据服务。工具测试只在测试环境执行，展示经过脱敏的请求与响应。

写入类工具可以配置 `ALWAYS_APPROVE`、`POLICY_APPROVE` 或 `NO_APPROVAL`，由服务端策略判定。需要审批时持久化审批任务，模型不得自己批准。执行使用幂等键、明确超时和可审计结果；机器人动作工具调用现有 MissionService，不直接使用 MQTT 或数据库写入。权限或校验失败时生成失败轨迹且不发送请求。

## 8. 流程与任务管理

流程为带版本的有向无环图，节点限于开始、模型、知识检索、工具、条件、并行汇合、人工审批和结束。保存时校验无环、端口类型、必需配置、可达结束节点和最大并行度。条件节点只读取受控上下文字段，不执行任意代码。每个运行实例固定流程版本；任务及节点状态、输入摘要、输出摘要、重试次数、超时和错误落 MySQL。

状态包括 `PENDING/RUNNING/WAITING_APPROVAL/PAUSED/SUCCEEDED/FAILED/CANCELLED`。并行节点受租户并发上限控制；失败策略按节点选择停止、有限重试或指定补救分支。审批完成、暂停和恢复均检查任务状态版本，防止重复执行。进程重启后可从持久化状态恢复；对外部写入步骤依赖幂等键并检查上次调用结果。

## 9. 会话与记忆

扩展现有会话与消息表，增加版本、渠道主体、归属范围、失效时间和删除时间。后台按租户和权限查询历史会话与消息；用户只访问自己的会话，机器人会话还须验证机器人/成员授权。会话上下文按 Token 预算截取或摘要；长期记忆与原始会话分开存储。

记忆范围为 `SESSION/MEMBER/MEMBER_ROBOT/ROBOT`，每条记忆带租户、主体、来源、可信度、保存期限和删除状态。匿名或低置信身份不写成员记忆。读取先验证完整归属键；删除会话或记忆时取消后续检索并清理关联索引。管理员可设置默认保存期限和清理策略，长期记忆可由有权主体查看与删除。原始语音不默认持久保存。

## 10. 发布与渠道

测试运行只读取 TEST 版本，生产网页和机器人只读取 PRODUCTION 版本。发布前校验当前版本实际引用的模型、知识库、工具、流程和必要权限是否可用。第一交付段执行两入口冒烟验证；第三交付段加入必选回归测试集，失败不能发布。保留发布历史和回滚入口，回滚后新会话使用目标旧版本。

网页文本入口使用后台登录及智能体使用权限，提供会话列表、输入、流式回复、引用与任务状态。机器人入口继续使用设备身份和机器人绑定。未来企业应用接入必须创建独立渠道凭据和授权策略，不复用后台管理员 Token。管理后台八个模块使用本项目后端接口与字段，配置、执行、审批和排错操作各有服务端权限点及菜单按钮权限。

## 11. 运行监控与评测

每次运行有根执行 ID；模型、知识检索、工具、审批和流程节点写入子轨迹，记录开始/结束、状态、耗时、错误分类、Token、费用、引用和脱敏结果。轨迹查询按租户和操作者权限过滤。对超时、错误率、额度耗尽、索引失败和等待审批超期提供阈值告警；告警记录可查询并支持后续通知渠道扩展。

`ai_eval_dataset`、`ai_eval_case`、`ai_eval_run` 保存固定输入、期望行为和测试结果。至少覆盖：回答内容/引用检查、工具选择及参数、流程路径、权限拒绝和失败降级。每次评测固定智能体版本及数据集版本，记录逐案例结果和汇总指标，便于发布前回归比较；涉及外部写入的案例使用测试替身而不实际执行生产操作。

## 12. 分段实施与验收

该范围拆成三个连续交付段，每段都提交可运行的前后端、数据库升级脚本和必要测试：

1. **基础运行与发布**：智能体/模型配置、不可变版本、TEST/PRODUCTION 发布与回滚、机器人语音接入版本、网页文本流、基础会话与轨迹。验收为同一版本在两个渠道运行、租户隔离、草稿修改不影响生产以及回滚仅作用于新会话。
2. **知识、工具与流程**：Qdrant 索引、文档权限和引用、工具契约/凭据/审批、持久化流程任务及暂停恢复。验收为两渠道均可检索授权资料、调用受控工具，条件/并行/审批流程在重启后保持正确状态。
3. **记忆、监控与评测完善**：记忆归属与保留删除、费用额度、告警、测试集与回归评测、完整后台页面。验收为权限和删除生效、用量/错误可追踪、失败回归阻止发布。

所有段均需通过 AI 模块单元与集成测试、前端类型与构建检查、存量数据库升级验证及两入口端到端验证。安全测试覆盖跨租户访问、越权知识检索、工具目标地址与写入审批、敏感凭据泄露。不得把未接通后端的旧 AI 页面计入验收。
